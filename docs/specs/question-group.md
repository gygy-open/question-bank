# 产品规格说明书：题组（教学微模块）管理

## 1. 背景与痛点 (Background)
目前系统的题库是以“单题”为最小颗粒度进行运作和组卷的。但在实际备课（尤其是编排导学案、专题讲义）场景中，老师通常是以“某一种解题方法”、“某一个微型知识点”为单位组织内容的——例如“向量数量积-坐标法”，里面包含了**知识讲解**以及配套的**若干例题与练习**。
如果每次排版讲义都要重新录入文字、去题库捞题，会导致大量的重复劳动。“题组”功能旨在提供一种“内容打包/预制件”能力，提升二次排版组卷的效率。

## 2. 目标 (Goals)
- 支持用户创建包含“富文本讲解”及“关联若干题目”的“题组（Question Group）”。
- 完善题组的元数据（学科、难度、知识点），使其可以在题库资源中被检索。
- 在组卷（试题篮）环节，支持将整套题组一键柔性打平推入试卷，实现讲义内容的快速搭建。

## 3. 范围 (Scope)

### In Scope
- 题组的 CRUD（创建、读取、更新、删除）。
- 单题与题组的归属关系管理（一对多引用）。
- 题库工作台（Question Bank）新增“单题模式”与“题组模式”双重视图。
- 单个/批量题目添加入某题组的快捷交互。
- 试题篮与组卷功能兼容题组形式（按序拆解为富文本块与单题落入试卷）。

### Out of Scope
- 多层级题组（题组内套子题组的俄罗斯套娃模式）暂不考虑，保持单层扁平化。
- 直接针对单题组的独立导出/打印（题组必须经过试题篮进入试卷/讲义进行输出）。
- 单题的改动如果不同步到题组（采用软引用模式，即题库原题修改，所有引用该题的题组自动同步生效）。

## 4. 用户故事与验收标准 (User Stories & Acceptance Criteria)

### 4.1 题组的创建与编辑
**作为** 教研老师，
**我希望** 能够创建一个题组，为其设置元信息、文字说明并添加题目，
**以便于** 我将一类具备相同教学逻辑的内容打包沉淀。

* **AC 4.1.1**: 在“资源库”界面有明确的【题组】Tab，点击【新建题组】唤出编辑界面。
* **AC 4.1.2**: 题组必须包含必填项：所属学科、题组标题。支持选填项：富文本讲解（支持公式/图片插入）、难度评估、知识点标签。
* **AC 4.1.3**: 题组下可以添加 0 到 N 道来自题库的题目。可以对题组内的题目自由拖拽排序。
* **AC 4.1.4**: 在题组详情视图中，题目应当仅表现为关联引用（存储 Question ID）。

### 4.2 题目的双向收集
**作为** 教研老师，
**我希望** 在浏览题库单题时也能随时将题目塞入某个题组，
**以便于** 我在日常找题时顺手完成模块整理。

* **AC 4.2.1**: 单题模式列表页，勾选题目后，底部批量操作悬浮栏增加【加入题组】按钮。
* **AC 4.2.2**: 点击加入后，弹出选择器支持搜索现有题组，或者原地快捷新建一个题组。

### 4.3 题组资源的检索
**作为** 教研老师，
**我希望** 能够通过学科、知识点检索题组库，
**以便于** 组卷时快速定位到需要的讲义模块。

* **AC 4.3.1**: 题组 Tab 下，筛选项应包含：学科、知识点树、难度。
* **AC 4.3.2**: 题组卡片应展示：题组名称、包含题目数量、知识点、以及“加入试题篮”快捷按钮。

### 4.4 柔性解包进入试题篮（核心）
**作为** 授课讲师，
**我希望** 把整个题组加入试题篮中编排讲义，并且在排版时能自主微调内容，
**以便于** 我根据每次不同班级的学情进行个性化删减。

* **AC 4.4.1**: 点击题组的“加入试题篮”，系统应将其视为“宏展开”：将题组的富文本说明变成一段独立的“文本块”，将内部题目保持原有顺序依次加入试题篮。
* **AC 4.4.2**: 移除试题篮中的某道该题组题目，仅影响当前正在编排的这份试卷/讲义，**不影响**资源库中该题组的原始定义。

## 5. 优先级评估 (MoSCoW)

* **Must have** (必须有): 题组模型建立，题组 CRUD，双向添加题目，题组进入试题篮（打散逻辑）。
* **Should have** (应该有): 题组管理列表侧的复合筛选（通过树形知识点过滤题组）。
* **Could have** (可以有): 给题组内挂载的单题打上“分类/角色标签”如“【例题】”、“【变式】”，展示时带上微标。
* **Won't have** (暂不考虑): 对题库外临时导入的纯外部题目直接组装题组（依然遵循先入库，后组装原则）。

## 6. 技术架构与演进关系 (Architecture & Dependencies)
* **前置依赖**：题组功能强依赖于 [Block Canvas (块级组卷排版引擎)](./block-canvas.md) 的底层抽象。**必须先实现 Block Canvas**，再开发题组功能。
* **模型复用**：废弃原计划的 `question_group_items` 独立表设计。题组在系统抽象中本质上是一个轻量的“微型出版物（Publication）”，其内容载体统一复用 `PublicationBlock` 表。
* **编辑器复用**：题组的编辑界面直接嵌入并复用通用的 `<BlockCanvas>` 组件，只需指定上下文以禁用某些业务无关的设置，利用已积木化的 `TextBlock` 和 `QuestionBlock` 即能快速完成题组录入。
* **柔性解包机制（Deep Copy）**：加入试题篮的操作，在新的架构下对应于一次 Blocks 的“克隆（Deep Copy）”。即抓取出资源库题组的原始 Blocks，抽离关联 ID 后，作为新下发的区块组塞入目前排版文档（目标 Publication）的队尾。这样就实现了原库与当下试题材料的彻底解耦和柔性排版。
