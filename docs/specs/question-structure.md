# 题干结构化：架构与交互方案

- 状态：草案
- 依据：[ADR：元素模型](./adr-question-element-model.md)、老师反馈（2026-11-04）、PR #28 / #29

## 1. 范围

老师的顺序是：**先把题干拆明白，再谈步骤、分析、组卷、命题、学情**。本方案据此分期，第一期只做题干。

| 期 | 内容 | 前置条件 |
| --- | --- | --- |
| **一：题干拆解** | 条件 / 设问拆解、原文定位、自动体检、审核、按元素检索 | — |
| **二：元素归纳** | 未归类元素聚类 → 老师确认 → 形成元素类型体系 | 一期积累足量已审数据 |
| 三：解题步骤与难度 | 思维动作、步骤权重、思维量难度 | 元素类型基本稳定 |
| 四：变式与命题 | 参数槽、元素替换 / 组合、自动校验 | 三期 |
| 五：学情 | 常见错误、作答数据关联 | 有作答数据来源 |

下文的数据模型、能力、界面均只覆盖一、二期；三期以后只保留扩展点，不建表。

## 2. 三套分类，各管各的

| 分类 | 定位 | 来源 | 维护 | 现状 |
| --- | --- | --- | --- | --- |
| 知识点 | 课本 / 课标内容，层级固定，形态稳定 | 老师筛选后导入 | 学科负责人 | 已有 `knowledge_points`，**不改** |
| 标签 | 知识点以外的分类（来源、年份、题型特征…） | 老师筛选后导入 | 学科负责人 | 已有 `tags` / `tag_categories`，**不改** |
| **元素类型**（新） | 题干条件 / 设问的结构类别 | **由题目归纳**，老师确认后生效 | 学科负责人 | 本方案新增 |

元素类型与前两者的区别：它不能预先写全，必须从大量题目中归纳；但归纳结果仍需老师确认才生效，不由 AI 直接定。

## 3. 概念模型

```
题目（questions，不改）          材料（stimuli，不改）
   │ 1:N                            │ 1:N
   ▼                                ▼
拆解快照 struct_run  ←── target 指向题目或材料，记录拆解时的原文快照与版本
   ├─ 条件 struct_element ── type → 元素类型（可空，待归纳）
   │                       └─ ref → 材料拆解中的条件（共享）
   └─ 设问 struct_ask ──── type → 设问类型
                         └─ 依赖哪些条件
元素类型 struct_type：按学科的树；第一层为领域（数学：代数 / 几何 / 统计）
```

要点：

1. **只拆题干**。输入为题干（含选项）纯文本，不传答案、解析。
2. **先分条件与设问**，条件再按领域归类（数学：代数→式的结构，几何→形的结构，统计→统计量的结构）。领域是元素类型树的第一层，不同学科可配置不同的第一层。
3. **拆解是快照**（沿用 #29）：一题可有多次拆解（AI、人工、换模型），同一时刻最多一个“已采纳”。
4. **原文快照**：拆解时把题干转成纯文本（`rich_doc_to_plain_text`）存进快照，条件 / 设问的起止位置都指向这份快照，而不是 RichDoc。题目被编辑后，`questions.content_revision` 与快照记录的版本不一致，拆解自动显示为“已过期”。
5. **材料共享**：材料（`stimuli`）单独拆解一次；小题的条件可以引用材料拆解中的条件，不重复拆。这与 ADR 的“元素可被多题共享”一致，又不改动 `stimuli`。

## 4. 数据模型（一、二期）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `struct_types` | `subject_id`, `parent_id`, `kind`(condition/ask), `code`, `name`, `definition`, `examples`(JSON), `status`(candidate/active/deprecated), `sort_order` | 按学科的树。新增类型只是插一行，不发版 |
| `struct_runs` | `target_type`(question/stimulus), `target_id`, `subject_id`, `source_revision`, `stem_text`, `origin`(ai/human), `model`, `prompt_version`, `job_id`, `state`(draft/accepted/rejected/superseded), `check_report`(JSON), `check_errors`, `check_warnings`, `created_by`, `reviewed_by`, `reviewed_at` | 一个目标最多一个 `accepted`、一个 `draft`（新草稿取代旧草稿），由服务层保证；`check_errors/warnings` 供审核队列筛选与“有错误的排前面” |
| `struct_elements` | `run_id`, `ordinal`, `content`, `type_id`(可空), `type_hint`, `facet`(可空), `span_start/end`, `ref_element_id`(可空) | `type_hint` 是 AI 对未归类条件给出的自由描述，供二期聚类；`facet` 保留 #29 的 quant/qual/proc/form，作为可选检索维度 |
| `struct_asks` | `run_id`, `ordinal`, `content`, `type_id`, `span_start/end` | — |
| `struct_ask_elements` | `ask_id`, `element_id` | 设问依赖哪些条件 |

不建的：步骤、步骤产出、参数槽、元素组、常见错误、解题方法词表（三期起按需加）。元素角色不建表：条件 / 设问已分表，其余细分用 `facet`。

元素类型树的根节点在学科首次使用结构化时自动建立（`types.ensure_roots`，幂等），新建的学科同样适用，桌面版无需手动跑脚本：数学为代数 / 几何 / 统计 + 设问，其他学科为条件 + 设问。根之下的具体类型不预置，由老师导入或从拆解结果中归纳。

题干快照 `stem_text` 由 `services/structure/text.py` 生成：题干 + 选项（每行 `A. ...`），公式保留 `$...$`，图片 / 音频 / 填空位用 `[image]` / `[audio]` / `____` 占位。

## 5. 处理流程

```
触发 ──► 拆解任务入队 ──► worker 调 AI（只给题干）──► 自动体检 ──► draft
                                                        │ 有 error：带体检结果重试 1 次
                                                        ▼
                                  审核：采纳 / 修改后采纳 / 驳回 ──► accepted（进入检索）
```

| 环节 | 设计 |
| --- | --- |
| 触发 | ① 题目页“拆解”按钮；② 题库列表批量操作；③ 题目入库（导入提交、新建、审核通过）后自动入队，按学科开关；④ 存量回填（后台限速） |
| 队列 | 通用任务表 `jobs`（见 5.1），拆解为 `type=structure.decompose` |
| AI | 使用“文本”用途的模型，经 `AIProvider.generate_json` 调用；提示词 `AI_STRUCT_DECOMPOSE_PROMPT` 登记在学科提示词注册表，可按学科覆盖，版本（默认 `v1`，覆盖为 `custom`）写入快照。提示词中给出该学科当前 `active` 的类型树；无匹配时 `type_id` 留空、写 `type_hint` |
| 体检 | 沿用 #28 的 `check_structure`：原文找不到、重复、设问符号悬空、一条多断言；结果存 `check_report` |
| 过期 | 题目内容修改后，已采纳的拆解显示“已过期”，可一键重拆；不自动覆盖 |
| 开关 | 系统设置 `structure.enabled`（总开关，缺省开）+ 学科设置 `structure.auto_decompose`（存 `subject_settings`，缺省关） |
| 材料 | 小题所属材料还没有拆解时，job 先拆材料（存为待审），再把材料条件作为可引用列表交给小题的拆解 |

### 5.1 通用任务表 `jobs`

所有后台任务共用一张表管理**执行状态**，业务表通过 `job_id` 关联、只存**业务状态**。

| 表 | 内容 |
| --- | --- |
| `jobs` | `type`、`status`(pending/running/paused/succeeded/failed/cancelled)、`priority`、`attempts`、`max_attempts`、`run_after`、`locked_until`、`provider_id`、`paused_reason`、`progress`、`error`、`payload`(JSON)、`subject_id`、`user_id`、`locale`、`idempotency_key` |
| 业务表 | 通过 `jobs.target_type` + `target_id` 关联（多态，不设外键），业务表不另存 `job_id`；`struct_runs.job_id` 只记录产生该快照的 job。审核中 / 已入库等属于业务状态，留在业务表 |
| 投影 | 处理器的 `project()` 在同一事务内把执行状态写回业务表。导入任务原有的 status / paused_reason / provider_id / error_message / progress 字段保留，作为 job 状态的投影，供导入页面、桌面通知与各类查询使用 |

- worker 按 `type` 分派处理函数；领取任务、重试、按提供方暂停与恢复（`ai_errors`）、熔断、取消、重启后重新入队只实现一次。
- 同一提供方故障时，导入与拆解等所有任务一起暂停、一起恢复。
- 优先级：用户手动触发 > 入库自动触发 > 存量回填，回填不会堵住用户的导入。
- 节奏：一期新建 `jobs`、改造 worker 分派，并先把导入迁移到 `jobs`（在结构化之前完成，导入相关测试全部通过后再继续）；用 `data_migrations` 回填存量导入任务，`/imports` 接口与页面不变。

## 6. 能力与接口

写操作注册到 `capabilities/`（HTTP、站内 AI、MCP 共用）；读操作与题目域一致，不进能力层，由 REST 端点直接调用服务，MCP 另有同等门禁的只读工具。

| 能力 / 接口 | 用途 | 权限 | MCP |
| --- | --- | --- | --- |
| `structure.decompose` | 单个 / 批量入队拆解（题目或材料） | 逐条：可见 + 学科编辑 | ✓ |
| `structure.save` | 保存人工修改（生成 `origin=human` 的新快照，可同时采纳） | 学科编辑 | ✓（只能存为待审） |
| `structure.review` | 采纳 / 驳回（批量） | 逐条：可见 + 学科编辑 | ✗ |
| `structure.backfill` | 为学科内尚未拆解的题排队（最低优先级） | 学科管理 | ✗ |
| `struct_type.create/update/delete/merge/import` | 元素类型树维护 | 学科「编辑知识点 / 标签」权限 | ✗ |
| `GET /structure/targets/{type}/{id}` | 结构化全貌（已采纳、待审、进行中的 job） | 可见 | `get_question_structure` |
| `GET /structure/types`、`/types/export` | 类型树（含引用题数）与导出 | 学科查看 | `list_structure_types` |
| `GET /structure/questions/{id}/similar` | 同结构题（类型集合 Jaccard 相似度） | 可见 | `find_similar_structure_questions` |
| `GET /structure/review-queue` | 待审拆解（错误优先） | 学科查看 | ✗ |
| `GET /structure/stats`、`POST /structure/distribution` | 首页统计、组卷分布 | 学科查看 / 可见 | ✗ |
| 题目检索（扩展现有） | `GET /questions`、站内 AI 与 MCP 的 `search_questions` 新增 `struct_type_ids`（含子类型）、`struct_state`；列表项返回 `struct_state` | 同现有 | ✓ |
| `struct_type.induce`（二期） | 生成候选类型聚类 | 学科管理 | ✗ |

## 8. 界面

### 8.1 题干结构面板（题目详情 / 编辑弹窗内的标签页）

```
┌ 题干结构 ────────────────────────────── [已采纳 ✓] [重新拆解] [编辑] ┐
│ 原文                                                                │
│  已知函数 [f(x)=x³+ax+2]₁ [存在 3 个零点]₂，则 [a 的取值范围]Q1 是…  │
│                                                                     │
│ 条件                                                                 │
│  1  f(x)=x³+ax+2        代数 › 函数解析式 › 含参三次函数              │
│  2  f(x) 有 3 个零点     代数 › 函数性质 › 零点个数                    │
│ 设问                                                                 │
│  Q1 求 a 的取值范围      求参数范围      依赖：1、2                    │
│                                                                     │
│ ⚠ 体检：无问题                       拆解：AI · qwen3.8-max · v1     │
└─────────────────────────────────────────────────────────────────────┘
```

- 悬停条件 ↔ 原文对应片段高亮；领域用颜色区分（代数 / 几何 / 统计）。
- 未归类的条件显示 AI 的 `type_hint`（灰色、斜体），提示“待归纳”。
- 体检问题就近显示在对应条目上（error 红、warning 黄）。
- **编辑模式**：在原文中选中文字 → 浮出“设为条件 / 设为设问”；条目可改写表述、选类型、拖动排序、合并 / 拆分。保存生成新的人工快照，不覆盖 AI 结果，便于对比。
- 已过期时，原文区显示“题目已修改”，提供“重新拆解”。
- 材料题的小题：共享条件带“来自材料”标记，点击跳转材料的拆解。

### 8.2 拆解审核（题库下新增页面 `/structure/review`）

参照导入审核的交互：

- 左侧队列：待审拆解，可按学科、体检结果（有错误 / 仅提醒 / 无问题）、来源筛选；默认把有错误的排前面。
- 右侧：8.1 的面板（编辑模式）。
- 快捷键：`J/K` 上下题，`A` 采纳，`E` 编辑，`R` 重新拆解，`X` 驳回。
- 批量：勾选“无问题”的条目一键采纳。

### 8.3 元素类型管理（题库设置下，参照知识点页面）

- **类型树**：按学科，第一层为领域；节点含名称、定义、正反例、被引用题数。支持新增、改名、移动、合并（合并时迁移引用）、停用、导入导出。
- **待归纳**（二期）：展示 AI 聚类出的候选组——候选名称、条数、示例条件、相似的已有类型。操作：新建为类型 / 并入已有类型 / 忽略。确认后，组内条件自动回填类型。

### 8.4 其他

- 题库列表项：一个小徽标显示结构状态；筛选栏增加“元素类型”。
- 学科设置：“入库后自动拆解”开关。
- 命名：现有 `QuestionStructureSheet.vue` 展示的是材料与小题关系，改名为 `QuestionRelationsSheet.vue`，“结构”一词留给本功能。
- 所有文案走 i18n 流程。

## 10. 实施顺序（一期）

1. 通用任务表 `jobs` + worker 按类型分派；导入迁移到 `jobs`。
2. 结构化表与迁移、体检（参考 #28 / #29 重写，见第 9 节）。
3. 拆解服务 + 提示词；能力与 API、MCP 映射、题目检索筛选。
4. 题干结构面板（只读 → 编辑）。
5. 审核页、题库筛选与徽标。
6. 元素类型管理（类型树）、组卷筛选与分布、首页统计。
7. 用老师提供的题目试跑，统计体检通过率与审核修改率，再决定是否开启“入库自动拆解”。
