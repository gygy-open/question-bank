# 题干结构化：架构与交互方案

- 状态：一至四期已实现（分支 `feat/question-structure`）；五期（学情）暂缓
- 依据：[ADR：元素模型](./adr-question-element-model.md)、老师反馈（2026-11-04）、PR #28 / #29、作者分支 `laozhudu/feat/element-schema`（2026-11-04，见第 12 节）

## 1. 范围

老师的顺序是：**先把题干拆明白，再谈步骤、分析、组卷、命题、学情**。本方案据此分期，第一期只做题干。

| 期 | 内容 | 前置条件 | 状态 |
| --- | --- | --- | --- |
| **一：题干拆解** | 条件 / 设问拆解、原文定位、自动体检、审核、按结构检索 | — | ✅ 已实现 |
| 一·增强 | 同源检索（按元素内容、参数模式）；Agent 来源标记 | 一期 | ✅ 已实现（§12.3 N3、N5） |
| **二：元素归纳** | 未归类元素聚类 → 老师确认 → 形成元素类型体系 | 一期积累足量已审数据 | ✅ 已实现（§12.3 归纳） |
| **参数槽与变式**（提前） | 题干中的可替换参数、按参数生成变式题 | 一期 | ✅ 已实现（§12.3 N1） |
| 三：解题步骤与难度 | 解答快照、思维动作、步骤权重、思维量难度；类型 ↔ 知识点映射 | 元素类型基本稳定 | ✅ 已实现（§12.3 N7、N8） |
| 四：元素重组与命题 | 元素组整体替换、跨题拼装原创命题 | 参数槽、三期 | ✅ 已实现（§12.3 N2、N4） |
| 五：学情 | 作答记录、步骤级错因、元素掌握度 | 三期 + 有作答数据来源 | 暂缓（§12.3 N6） |

参数槽只依赖题干拆解，且是变式命题的直接抓手，因此从原四期提前到三期之前（2026-11-05 决定）。

§3–§10 描述一、二期（已实现部分以代码为准）；之后各期的设计见 §12。

## 2. 三套分类，各管各的

| 分类 | 定位 | 来源 | 维护 | 现状 |
| --- | --- | --- | --- | --- |
| 知识点 | 课本 / 课标内容，层级固定，形态稳定 | 老师筛选后导入 | 学科负责人 | 已有 `knowledge_points`，**不改** |
| 标签 | 知识点以外的分类（来源、年份、题型特征…） | 老师筛选后导入 | 学科负责人 | 已有 `tags` / `tag_categories`，**不改** |
| **元素类型**（新） | 题干条件 / 设问的结构类别 | **由题目归纳**，老师确认后生效 | 学科负责人 | 本方案新增 |

元素类型与前两者的区别：它不能预先写全，必须从大量题目中归纳；但归纳结果仍需老师确认才生效，不由 AI 直接定。

## 3. 概念模型

```
题目（questions，不改）          材料（stimuli，不改）
   │ 1:N                            │ 1:N
   ▼                                ▼
拆解快照 struct_run  ←── target 指向题目或材料，记录拆解时的原文快照与版本
   ├─ 条件 struct_element ── type → 元素类型（可空，待归纳）
   │                       └─ ref → 材料拆解中的条件（共享）
   └─ 设问 struct_ask ──── type → 设问类型
                         └─ 依赖哪些条件
元素类型 struct_type：按学科的树；第一层为领域（数学：代数 / 几何 / 统计）
```

要点：

1. **只拆题干**。输入为题干（含选项）纯文本，不传答案、解析。
2. **先分条件与设问**，条件再按领域归类（数学：代数→式的结构，几何→形的结构，统计→统计量的结构）。领域是元素类型树的第一层，不同学科可配置不同的第一层。
3. **拆解是快照**（沿用 #29）：一题可有多次拆解（AI、人工、换模型），同一时刻最多一个“已采纳”。
4. **原文快照**：拆解时把题干转成纯文本（`rich_doc_to_plain_text`）存进快照，条件 / 设问的起止位置都指向这份快照，而不是 RichDoc。题目被编辑后，`questions.content_revision` 与快照记录的版本不一致，拆解自动显示为“已过期”。
5. **材料共享**：材料（`stimuli`）单独拆解一次；小题的条件可以引用材料拆解中的条件，不重复拆。这与 ADR 的“元素可被多题共享”一致，又不改动 `stimuli`。

## 4. 数据模型（一、二期）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `struct_types` | `subject_id`, `parent_id`, `kind`(condition/ask), `code`, `name`, `definition`, `examples`(JSON), `status`(candidate/active/deprecated), `sort_order` | 按学科的树。新增类型只是插一行，不发版 |
| `struct_runs` | `target_type`(question/stimulus), `target_id`, `subject_id`, `source_revision`, `stem_text`, `origin`(ai/human), `model`, `prompt_version`, `job_id`, `state`(draft/accepted/rejected/superseded), `check_report`(JSON), `check_errors`, `check_warnings`, `created_by`, `reviewed_by`, `reviewed_at` | 一个目标最多一个 `accepted`、一个 `draft`（新草稿取代旧草稿），由服务层保证；`check_errors/warnings` 供审核队列筛选与“有错误的排前面” |
| `struct_elements` | `run_id`, `ordinal`, `content`, `type_id`(可空), `type_hint`, `facet`(可空), `span_start/end`, `ref_element_id`(可空) | `type_hint` 是 AI 对未归类条件给出的自由描述，供二期聚类；`facet` 保留 #29 的 quant/qual/proc/form，作为可选检索维度 |
| `struct_asks` | `run_id`, `ordinal`, `content`, `type_id`, `span_start/end` | — |
| `struct_ask_elements` | `ask_id`, `element_id` | 设问依赖哪些条件 |

不建的：步骤、步骤产出、参数槽、元素组、常见错误、解题方法词表（三期起按需加）。元素角色不建表：条件 / 设问已分表，其余细分用 `facet`。

元素类型树的根节点在学科首次使用结构化时自动建立（`types.ensure_roots`，幂等），新建的学科同样适用，桌面版无需手动跑脚本：数学为代数 / 几何 / 统计 + 设问，其他学科为条件 + 设问。根之下的具体类型不预置，由老师导入或从拆解结果中归纳。

题干快照 `stem_text` 由 `services/structure/text.py` 生成：题干 + 选项（每行 `A. ...`），公式保留 `$...$`，图片 / 音频 / 填空位用 `[image]` / `[audio]` / `____` 占位。

## 5. 处理流程

```
触发 ──► 拆解任务入队 ──► worker 调 AI（只给题干）──► 自动体检 ──► draft
                                                        │ 有 error：带体检结果重试 1 次
                                                        ▼
                                  审核：采纳 / 修改后采纳 / 驳回 ──► accepted（进入检索）
```

| 环节 | 设计 |
| --- | --- |
| 触发 | ① 题目页“拆解”按钮；② 题库列表批量操作；③ 题目入库（导入提交、新建、审核通过）后自动入队，按学科开关；④ 存量回填（后台限速） |
| 队列 | 通用任务表 `jobs`（见 5.1），拆解为 `type=structure.decompose` |
| AI | 使用“文本”用途的模型，经 `AIProvider.generate_json` 调用；提示词 `AI_STRUCT_DECOMPOSE_PROMPT` 登记在学科提示词注册表，可按学科覆盖，版本（默认 `v1`，覆盖为 `custom`）写入快照。提示词中给出该学科当前 `active` 的类型树；无匹配时 `type_id` 留空、写 `type_hint` |
| 体检 | 沿用 #28 的 `check_structure`：原文找不到、重复、设问符号悬空、一条多断言；结果存 `check_report` |
| 过期 | 题目内容修改后，已采纳的拆解显示“已过期”，可一键重拆；不自动覆盖 |
| 开关 | 系统设置 `structure.enabled`（总开关，缺省开）+ 学科设置 `structure.auto_decompose`（存 `subject_settings`，缺省关） |
| 材料 | 小题所属材料还没有拆解时，job 先拆材料（存为待审），再把材料条件作为可引用列表交给小题的拆解 |

### 5.1 通用任务表 `jobs`

所有后台任务共用一张表管理**执行状态**，业务表通过 `job_id` 关联、只存**业务状态**。

| 表 | 内容 |
| --- | --- |
| `jobs` | `type`、`status`(pending/running/paused/succeeded/failed/cancelled)、`priority`、`attempts`、`max_attempts`、`run_after`、`locked_until`、`provider_id`、`paused_reason`、`progress`、`error`、`payload`(JSON)、`subject_id`、`user_id`、`locale`、`idempotency_key` |
| 业务表 | 通过 `jobs.target_type` + `target_id` 关联（多态，不设外键），业务表不另存 `job_id`；`struct_runs.job_id` 只记录产生该快照的 job。审核中 / 已入库等属于业务状态，留在业务表 |
| 投影 | 处理器的 `project()` 在同一事务内把执行状态写回业务表。导入任务原有的 status / paused_reason / provider_id / error_message / progress 字段保留，作为 job 状态的投影，供导入页面、桌面通知与各类查询使用 |

- worker 按 `type` 分派处理函数；领取任务、重试、按提供方暂停与恢复（`ai_errors`）、熔断、取消、重启后重新入队只实现一次。
- 同一提供方故障时，导入与拆解等所有任务一起暂停、一起恢复。
- 优先级：用户手动触发 > 入库自动触发 > 存量回填，回填不会堵住用户的导入。
- 节奏：一期新建 `jobs`、改造 worker 分派，并先把导入迁移到 `jobs`（在结构化之前完成，导入相关测试全部通过后再继续）；用 `data_migrations` 回填存量导入任务，`/imports` 接口与页面不变。

## 6. 能力与接口

写操作注册到 `capabilities/`（HTTP、站内 AI、MCP 共用）；读操作与题目域一致，不进能力层，由 REST 端点直接调用服务，MCP 另有同等门禁的只读工具。

| 能力 / 接口 | 用途 | 权限 | MCP |
| --- | --- | --- | --- |
| `structure.decompose` | 单个 / 批量入队拆解（题目或材料） | 逐条：可见 + 学科编辑 | ✓ |
| `structure.save` | 保存人工修改（生成 `origin=human` 的新快照，可同时采纳） | 学科编辑 | ✓（只能存为待审） |
| `structure.review` | 采纳 / 驳回（批量） | 逐条：可见 + 学科编辑 | ✗ |
| `structure.backfill` | 为学科内尚未拆解的题排队（最低优先级） | 学科管理 | ✗ |
| `struct_type.create/update/delete/merge/import` | 元素类型树维护 | 学科「编辑知识点 / 标签」权限 | ✗ |
| `GET /structure/targets/{type}/{id}` | 结构化全貌（已采纳、待审、进行中的 job） | 可见 | `get_question_structure` |
| `GET /structure/types`、`/types/export` | 类型树（含引用题数）与导出 | 学科查看 | `list_structure_types` |
| `GET /structure/questions/{id}/similar` | 同结构题（类型集合 Jaccard 相似度） | 可见 | `find_similar_structure_questions` |
| `GET /structure/review-queue` | 待审拆解（错误优先） | 学科查看 | ✗ |
| `GET /structure/stats`、`POST /structure/distribution` | 首页统计、组卷分布 | 学科查看 / 可见 | ✗ |
| 题目检索（扩展现有） | `GET /questions`、站内 AI 与 MCP 的 `search_questions` 新增 `struct_type_ids`（含子类型）、`struct_state`；列表项返回 `struct_state` | 同现有 | ✓ |
| `struct_type.induce`（二期） | 生成候选类型聚类 | 学科管理 | ✗ |

## 8. 界面

### 8.1 题干结构面板（题目详情 / 编辑弹窗内的标签页）

```
┌ 题干结构 ────────────────────────────── [已采纳 ✓] [重新拆解] [编辑] ┐
│ 原文                                                                │
│  已知函数 [f(x)=x³+ax+2]₁ [存在 3 个零点]₂，则 [a 的取值范围]Q1 是…  │
│                                                                     │
│ 条件                                                                 │
│  1  f(x)=x³+ax+2        代数 › 函数解析式 › 含参三次函数              │
│  2  f(x) 有 3 个零点     代数 › 函数性质 › 零点个数                    │
│ 设问                                                                 │
│  Q1 求 a 的取值范围      求参数范围      依赖：1、2                    │
│                                                                     │
│ ⚠ 体检：无问题                       拆解：AI · qwen3.8-max · v1     │
└─────────────────────────────────────────────────────────────────────┘
```

- 悬停条件 ↔ 原文对应片段高亮；领域用颜色区分（代数 / 几何 / 统计）。
- 未归类的条件显示 AI 的 `type_hint`（灰色、斜体），提示“待归纳”。
- 体检问题就近显示在对应条目上（error 红、warning 黄）。
- **编辑模式**：在原文中选中文字 → 浮出“设为条件 / 设为设问”；条目可改写表述、选类型、拖动排序、合并 / 拆分。保存生成新的人工快照，不覆盖 AI 结果，便于对比。
- 已过期时，原文区显示“题目已修改”，提供“重新拆解”。
- 材料题的小题：共享条件带“来自材料”标记，点击跳转材料的拆解。

### 8.2 拆解审核（题库下新增页面 `/structure/review`）

参照导入审核的交互：

- 左侧队列：待审拆解，可按学科、体检结果（有错误 / 仅提醒 / 无问题）、来源筛选；默认把有错误的排前面。
- 右侧：8.1 的面板（编辑模式）。
- 快捷键：`J/K` 上下题，`A` 采纳，`E` 编辑，`R` 重新拆解，`X` 驳回。
- 批量：勾选“无问题”的条目一键采纳。

### 8.3 元素类型管理（题库设置下，参照知识点页面）

- **类型树**：按学科，第一层为领域；节点含名称、定义、正反例、被引用题数。支持新增、改名、移动、合并（合并时迁移引用）、停用、导入导出。
- **待归纳**（二期）：展示 AI 聚类出的候选组——候选名称、条数、示例条件、相似的已有类型。操作：新建为类型 / 并入已有类型 / 忽略。确认后，组内条件自动回填类型。

### 8.4 其他

- 题库列表项：一个小徽标显示结构状态；筛选栏增加“元素类型”。
- 学科设置：“入库后自动拆解”开关。
- 命名：现有 `QuestionStructureSheet.vue` 展示的是材料与小题关系，改名为 `QuestionRelationsSheet.vue`，“结构”一词留给本功能。
- 所有文案走 i18n 流程。

## 12. 后续需求与设计

### 12.1 需求来源

PR 作者在自己的分支 `laozhudu/feat/element-schema` 上做了一轮扩展（2026-11-04）。该分支不合入（只同步了本方案的部分代码，拆解链路无法运行；新接口缺少权限判断），但其中的需求是成立的。这里把需求识别出来，按本方案的架构重新设计。

### 12.3 设计

所有设计遵守一期确立的约束：

- 拆解快照一经生成不可修改；修改即生成新快照。
- 写操作走能力层，按学科判权；读接口套用题目可见性过滤。
- 所有 AI 调用都是 `jobs` 里的任务，错误处理复用 `ai_errors`。
- AI 只产出待审结果，采纳由人在站内完成。
- 生成的新题一律作为**草稿题**走正常入库流程（查重 → 审核），不在结构化模块里直接产出可用题目。

#### N1 参数槽（提前到三期之前）

**数据**：`struct_params`，挂在快照上。

| 字段 | 说明 |
| --- | --- |
| `run_id`、`element_id` | 所属快照与条件（可空：参数在设问里时挂 `ask_id`） |
| `name` | 参数名，如 `a`、`常数项`、`点A坐标` |
| `span_start/end` | 参数值在 `stem_text` 中的位置。**按位置替换，不做字符串匹配**——否则把 `2` 换成 `5` 会连 `x^2` 一起改 |
| `value` | 原值（与 span 处的原文一致，由体检校验） |
| `slot_kind` | numeric / symbolic / point / interval / expression |
| `domain` | 允许取值（JSON：范围、枚举、约束说明），AI 建议、老师确认 |
| `replaceable` | 是否作为旋钮 |

**产生**：
- AI 拆解时一并标出候选参数（提示词升级 v3，参数作为条件 / 设问的子项输出）；体检新增两条：参数位置必须落在所属条目的原文区间内、`value` 与原文一致。
- 老师在面板编辑模式中选中原文 → 「设为参数」。
- 人工保存时参数随条目一并提交，因此新快照继承参数，不会因修改而丢失。

**变式**：新任务 `structure.variant`。
1. 输入：快照 id + 参数新值（老师填写，或让 AI 在 `domain` 内取值）。
2. 按 span 从后往前替换 `stem_text`，再把替换映射回 RichDoc（公式节点内替换 LaTeX，文本节点内替换文字）。
3. AI 重新解题，校验答案唯一、数值合理、干扰项仍有效（选择题）。
4. 通过 `question.derived.create` 生成草稿题，关系类型 `variant_of`；新题自动排队拆解。
5. 校验不通过时任务失败并给出原因，不生成题。

**界面**：结构面板中参数以下划线标出；「生成变式」对话框列出可替换参数、显示取值范围、预览替换后的题干；生成结果进入题库草稿。

#### 元素归纳（二期）

- 数据：`struct_type_candidates`（学科、kind、领域根、名称、描述、建议父节点、相似的已有类型、状态 pending / accepted / merged / ignored）+ `struct_type_candidate_items`（指向条件或设问）。
- 任务 `struct_type.induce`（学科管理权限）：收集已采纳快照中未归类的条目，按领域根分组 → 先按 `type_hint` 粗分组 → AI 合并成候选，体检保证每条恰好归入一个候选。同一学科只保留最新一批 pending 候选；未归类条目少于阈值时提示数据不足。
- 确认（§8.3「待归纳」）：新建为类型 / 并入已有类型 / 忽略；确认后组内条目原地回填 `type_id`（类型属于分类元数据，不生成新快照）。

#### N2 元素组（四期）

- 数据：`struct_element_groups(run_id, name, description, replaceable)` + `struct_element_group_items(group_id, element_id)`，属于快照，随人工保存继承。
- 替换候选来自**其他题已采纳快照中的元素组**，按类型组合匹配（同领域、同类型集合），保证替换进来的内容本身经过审核。
- 替换后同样走 `structure.variant` 的「改写 → 解题校验 → 草稿题」流水线。

#### N3 同源检索（一期增强）

- `struct_elements` 增加 `content_sig`：用查重模块的规范化（`question_dedup_core`）对条件内容取签名，建索引。
- 「同结构题」接口增加 `mode`：
  - `types`（现有）：设问类型 + 条件类型集合的 Jaccard；
  - `elements`：共享相同条件（`content_sig` 相同）的已采纳题；
  - `params`：参数模式相同（同类型条件 + 同名同类参数槽，值不同）——即「同一道题换了数」，依赖 N1。
- 统一套用可见性过滤；MCP 的 `find_similar_structure_questions` 同步增加 `mode`。

#### N4 跨题拼装（四期）

- 「命题篮」：在结构面板、同源检索结果中把条件 / 设问 / 元素组加入命题篮（类似试题篮，前端本地状态）。
- 新任务 `structure.compose`：输入所选元素与设问（可跨题），AI 写成一道通顺的新题并解答；体检 → 查重 → 自动拆解，**校验新题的结构与输入一致**（输入的元素都在、没有多出未声明的条件）→ 存为草稿题。
- 题目关系新增 `composed_from`，记录来源题，支持溯源。

#### N5 Agent 闭环（一期增强）

- 外部 Agent 自己拆解后用 `structure.save` 提交的链路已可用。
- `struct_runs.origin` 增加 `agent`：MCP 来源的保存记为 agent，审核页可按来源筛选，统计时能区分 AI（站内）/ Agent（外部）/ 人工。
- **开放范围（2026-11-05 修订）**：老师会让 Agent 经 MCP 自行处理数据、做验证（变式命题、改动元素等），因此对 MCP 开放：
  - 生成类：`structure.variant`、`structure.group_replace`、`structure.compose`、`solution.decompose` / `solution.save`；产出都是草稿题或待审拆解；
  - 类型树：`struct_type.*` 的增改删合并导入、`struct_type.induce` 与候选的确认（仍需用户本人有类型维护 / 学科管理权限）；
  - 只读工具：`get_structure_job`（任务进度与结果，只能看自己发起的）、`list_group_replacement_candidates`、`list_structure_type_candidates`、`get_question_solution`。
- **不开放**：采纳（`structure.review`、`solution.review`、保存时的 `accept`）与存量回填；参数取值范围的「确认」也只能由老师在站内完成。
- **可区分**：MCP 调用期间设置当前渠道（`app/core/channel.py` 的 ContextVar）。在其中排队的任务把渠道写进 payload，worker 执行时恢复。题目的 `created_via` 列默认取当前渠道，因此 Agent 直接创建的题、Agent 发起的变式 / 命题生成的题都记为 `mcp`；题库与 MCP `search_questions` 可按 `created_via` 筛选，列表显示「Agent」标记，便于清理测试数据。

#### N7 解题步骤与难度（三期）

- 步骤依赖解析而不是题干，单独建解答快照：`solution_runs(question_id, source_revision, solution_text, origin, state, ...)` → `solution_steps(ordinal, goal, method_type_id, result, is_key)` → `step_uses`（引用题干条件 id 或前序步骤）/ `step_produces`（中间结论，可被后续步骤引用）。
- 解答快照引用的是**已采纳**的题干快照；题干快照被取代时解答快照标记需要复核。
- 解题方法复用 `struct_types`（`kind=method`），权重存于类型定义（老师维护）。思维量难度 = 采纳解答中步骤权重之和（多解时取最小值，另存各解法的值）。
- 现有 1–5 难度保留并行（§11-4）。
- 常见错误（原 #29 `misconceptions`）挂在步骤上，来源分「干扰项」与「真实作答」两类；后者等 N6。

#### N8 元素对应知识点（三期）

- 在类型上映射知识点：`struct_type_knowledge_points(type_id, knowledge_point_id)`，老师在类型管理页维护。
- 不做逐条元素映射：类型有限，维护一次即可复用；元素逐条映射维护量过大。题目的知识点仍以题目自身标注为准，类型映射用于推荐与统计。

#### N6 学情（五期）

- 独立业务域，单独建表（答题卷、作答、步骤错因、元素掌握度），只通过 `question_id`、`solution_step_id`、`type_id` 引用结构化数据，不与题库表混在一起。
- 前置：N7（步骤级错因需要步骤）+ 确定作答数据来源（§11-6）。

### 12.5 实施顺序（1–5 已完成）

1. **一期增强**：N3（`content_sig` + `mode=elements`）、N5（`origin=agent`）。
2. **二期**：元素归纳（`struct_type.induce` → 候选 → 老师确认 → 回填类型）。
3. **参数槽与变式**：N1（数据、提示词 v3、体检、stem_text ↔ RichDoc 位置映射、面板标注、`structure.variant`），随后补 N3 的 `mode=params`。
4. **三期**：N7 解答快照与思维量难度、N8 类型 ↔ 知识点映射。
5. **四期**：N2 元素组、N4 跨题拼装（复用 N1 的「生成 → 校验 → 草稿题」流水线）。
6. **五期**：N6 学情——暂缓，作答数据来源确定后再启动。

### 12.6 实现备注（与设计的差异）

- **复核**：解答没有单独存 `needs_review` 标记，而是像题干拆解的「过期」一样实时判断（题目内容版本变化，或依据的题干拆解已不是当前采纳的那条）。
- **变式的选项**：选择题改参数后，原选项往往不再适用。校验时允许 AI 按原数量重写选项（`new_options`），界面提示老师核对；选项内嵌在题干里的题无法重写，判为不成立。本地兜底：选择题必须给出存在的正确选项，单选题恰好一个。
- **查重**：变式、组替换、拼装生成的题与原题本来就「高度相似」，只拦截完全重复的题。
- **元素组替换**：按区间直接替换多条条件会让题目读不通，因此与跨题拼装共用「AI 写题 → 重新拆解做一致性校验 → 解题校验 → 草稿题」流水线（`structure.compose` 任务，`mode=group`）。
- **一致性校验**：按规范化后内容的相似度（≥ 0.6）匹配输入条目与新题拆解出的条目；输入缺失或多出未给出的条件都算不一致，带着问题重写一次。
- **参数定位**：模型给出的 `occurrence` 有时按全部出现计数、有时只数独立出现，两种都兼容。
- **方法根**：已有学科在首次使用时自动补建「方法」根（不会重建老师删掉的其他根）。
- **试跑观察**（qwen3.7-max）：v3 提示词能合理标出系数、数据值、预测自变量等参数并给出取值范围；变式校验能发现「改参数后答案不在选项中」以及原题自身的数据矛盾（回归斜率与样本数据不符）。
