# 整卷导入并保存为可复用稿件

## 背景

### 问题定义

当前“智能导入”会把外部试卷拆分为题目，经审核后批量写入题库，但不会保留这份试卷已经形成的整卷组织成果。教师导入高一周测、月考卷或历年试卷后，只能得到零散题目；若想在原卷基础上替换少量题目并再次使用，仍需重新创建稿件、逐题加入并恢复题序和结构。

这使大量已经组好的存量试卷无法直接复用，也增加了遗漏题目、顺序错误和重复劳动的风险。

### 核心用户

- 需要整理并复用校内存量试卷的学科教师。
- 负责沉淀共享试卷资产的教研组成员。

### 现有能力与缺口

- 已有：外部素材按“上传 → 审核 → 入库”形成题库题目。
- 已有：稿件可保存题目编排、继续编辑、复制、定稿和导出。
- 缺口：同一次外部试卷导入不能同时形成“题库题目”和“可继续编辑的整卷稿件”。

## 目标

1. 让教师导入一份完整试卷时，可同时得到结构化题目和一份可复用稿件草稿。
2. 尽可能保留原卷的标题、题目顺序、分组、题号及可识别的分值，减少重新组卷工作。
3. 让教师能直接进入稿件替换、增删或调整少量题目，并沿用现有定稿、导出流程。
4. 保持现有“仅导入题目”流程可用，不强迫所有导入都创建稿件。
5. 保证两类结果状态清晰、可追溯，失败重试不会重复产生题目或稿件。

### 成功判定

- 教师导入整卷后，无需重新逐题组卷即可打开一份题序完整的稿件草稿。
- 教师可在该草稿中替换任意题目并完成保存、定稿和导出。
- 用户能从导入记录识别题目入库结果及关联稿件，且不会把部分成功误认为全部完成。

## 优先级（MoSCoW）

| 优先级 | 能力 |
| --- | --- |
| Must | 导入时可选择“仅导入题目”或“导入题目并保存为稿件” |
| Must | 同时保存时生成可编辑稿件草稿，并关联本次入库题目 |
| Must | 保留原卷题目顺序、父子题关系，以及可识别的标题、分组、题号和分值 |
| Must | 导入结果分别展示题目与稿件的成功、失败状态，并支持安全重试 |
| Must | 遵守学科、题目可见性及个人/共享稿件权限 |
| Must | 导入确认前，用户可编辑默认稿件名称，并选择个人/共享空间及目标目录 |
| Must | 部分题目未能成功入库时，由用户决定是否仅用已成功题目继续创建稿件，还是取消本次创建 |
| Should | 从导入历史一键打开关联稿件，并从稿件查看来源导入记录 |
| Should | 检测到本次上传文件与历史导入文件内容完全一致时提示可能重复，但不阻塞用户继续导入 |
| Should | 对无法识别的整卷结构给出明确提示，由用户导入后补充调整 |
| Could | 自动识别试卷元数据，如年级、考试类型、学期和考试时间，并用于稿件命名或分类 |
| Could | 提供“另存为新稿件”快捷入口，便于基于原卷制作不同班级或不同周次版本 |
| Won't | 首期不承诺与原文件像素级一致的页面版式还原 |
| Won't | 首期不因导入而自动定稿、自动发布或自动创建评测 |

## 用户故事

### US-01 选择导入结果（Must）

作为教师，我希望在确认导入前选择是否同时保存整卷稿件，以便区分零散素材导入和完整试卷导入。

#### US-01 验收标准

```gherkin
Given 教师进入导入确认阶段
Then “同时保存为稿件”选项默认关闭
And 只有教师主动勾选后，本次导入才会创建稿件
```

```gherkin
Given 教师已完成题目抽取并进入导入确认阶段
When 教师选择“仅导入题目”并确认
Then 系统只创建题库题目，不创建稿件
And 现有导入结果与导入历史行为保持不变
```

```gherkin
Given 教师已完成一份完整试卷的抽取
When 教师选择“导入题目并保存为稿件”并确认
Then 系统明确告知本次将产生题库题目和稿件草稿两类结果
```

```gherkin
Given 本次上传的文件与历史某次导入的文件内容完全一致
When 教师在上传阶段提交该文件
Then 系统提示“检测到与某次导入内容相同的文件”并展示那次导入的时间和关联稿件（若有）
And 教师仍可选择继续本次导入，不被强制阻止
```

```gherkin
Given 本次上传文件与历史导入文件仅部分题目相同或排版不同（非完全一致）
When 教师上传该文件
Then 系统不保证能识别并提示此类近似重复，需由教师自行判断
```

### US-02 生成可复用的整卷草稿（Must）

作为教师，我希望导入完成后得到一份已经排好题目的稿件，以便直接微调，而不是重新组卷。

#### US-02 验收标准

```gherkin
Given 原试卷包含标题、多个分组和按顺序排列的题目
And 教师选择同时保存为稿件
When 导入成功
Then 系统创建一份未定稿的可编辑稿件
And 稿件包含本次选中并成功入库的全部题目
And 题目顺序与审核确认时一致
And 已识别的标题、分组、题号和分值保留在稿件中
```

```gherkin
Given 原试卷包含材料题及其多个子题
When 系统生成稿件草稿
Then 材料与子题的从属关系和相对顺序得到保留
And 不会把子题错误地当作互不相关的独立大题
```

```gherkin
Given 某些分组、题号或分值无法可靠识别
When 教师确认同时保存为稿件
Then 系统在完成结果中指出缺失或需检查的内容
And 教师仍可打开稿件继续补充和调整
```

```gherkin
Given 教师在审核页删除了部分题目
When 教师确认同时保存为稿件
Then 系统询问教师对剩余题目是否重排题号
And 教师选择“重排”时，稿件按新顺序连续编号
And 教师选择“保留原题号”时，稿件沿用原题号并可能出现缺号
```

```gherkin
Given 原试卷包含当前稿件模型无法完整表达的结构（如复杂表格、多栏排版、特殊题型容器）
When 系统生成稿件草稿
Then 系统不因该结构而丢弃对应题目，也不阻塞整份稿件的生成
And 该结构以最接近的可用形式保留内容（如退化为普通文本/富文本块）
And 完成结果中列出“结构降级”提示，说明具体是哪部分内容
And 教师可在稿件编辑器中手动补充或重建该结构
```

```gherkin
Given 教师并排比对原始试卷与生成的稿件草稿
When 教师检查标题、大题分组、题目顺序、题号和分值
Then 教师无需手动调整这些内容即可认出这是同一份试卷
And 说明文字与参考答案模块的还原完整度不作为该判定的必要条件，达不到时按“结构降级”规则处理
```

### US-03 设置稿件归属与目标位置（Must）

作为教师，我希望决定导入稿件放到哪个空间（个人/共享）、哪个目录，并确认或修改默认稿件名称，以便符合试卷保密、协作和归档需要。

#### US-03 验收标准

```gherkin
Given 教师选择同时保存为稿件
When 系统展示稿件设置
Then 稿件名称默认取自可识别的试卷标题，若无法识别则取自导入文件名
And 教师可在确认导入前修改该名称
```

```gherkin
Given 教师选择同时保存为稿件
When 教师确认导入设置
Then 教师必须选择个人空间或共享空间
And 教师必须从该空间的目录树中选择一个目标目录（含根目录）
And 可选空间与目录只包含教师在当前学科有权创建的范围
```

```gherkin
Given 本次导入包含不允许进入共享稿件的私有题目
When 教师选择共享空间
Then 系统阻止确认并说明冲突原因
And 教师可改为个人空间或调整题目可见性后继续
```

### US-04 在原卷上做少量调整（Must）

作为教师，我希望打开导入稿件后替换、增删或移动少量题目，以便快速形成下一次可用试卷。

#### US-04 验收标准

```gherkin
Given 教师打开由导入生成的稿件草稿
When 教师替换其中一道题并保存
Then 其他未修改题目的内容、顺序、分组和分值保持不变
And 教师可继续使用现有定稿与导出能力
```

```gherkin

When 教师复制该稿件后编辑副本
Then 原稿件保持不变
And 副本可独立保存、定稿和导出
```

### US-05 查看双重导入结果与来源（Must）

作为教师，我希望清楚看到题目和稿件各自的导入结果，并能在两者之间追溯，以便确认整卷资产是否完整保存。

```gherkin
When 两类结果均创建成功
Then 完成页分别显示成功入库的题目数量和已创建的稿件名称
And 教师可直接打开该稿件
And 导入历史可识别本次关联稿件
```

```gherkin
Given 教师从关联稿件查看来源信息
When 来源导入记录仍可访问
Then 教师能识别该稿件来自哪次导入
And 能查看原始文件名称或导入批次名称
```

```gherkin
Given 稿件由本次导入创建时，系统已将来源文件名、导入批次和时间固化为稿件自身的不可变快照
When 来源导入文件之后被删除或清理
Then 教师仍能在稿件上看到创建时快照的来源文件名、批次和时间
And 该展示不依赖原始文件当前是否仍然存在
```

### US-06 处理部分失败和重试（Must）

作为教师，我希望创建题目或稿件失败时得到准确结果并安全重试，以免重复入库或误以为整卷已经保存。

#### US-06 验收标准

```gherkin
Given 教师选择同时保存为稿件
When 部分题目未能通过校验或未能成功入库
Then 系统在创建稿件前询问教师：仅用已成功题目继续创建稿件，还是取消本次创建
And 教师选择继续时，稿件只包含已成功入库的题目，并标记哪些题目被跳过
And 教师选择取消时，不创建稿件，已入库的题目不受影响
```

```gherkin
Given 教师选择同时保存为稿件
When 全部题目均未能成功入库
Then 系统不生成一份缺少有效关联题目的“成功”稿件
And 导入记录明确标记未完成及失败原因
```

```gherkin
Given 题目已经入库但稿件未能创建
When 教师查看完成结果
Then 系统分别显示“题目已入库”和“稿件创建失败”
And 教师可以仅重试创建稿件
And 重试不会重复创建已入库题目
```

```gherkin
Given 同一稿件创建请求已经成功
When 教师因网络中断再次发起重试
Then 系统不会创建内容相同的重复稿件
And 向教师返回已创建稿件的入口
```

```gherkin
Given 题目已成功入库但稿件创建失败
When 教师查看导入历史中本次任务的状态
Then 导入任务本身仍按现有状态枚举显示为已完成，不引入新的任务级状态值
And 稿件创建结果作为独立子状态单独展示（未生成 / 已生成 / 失败可重试）
And 教师只需看到具体动作提示（如“稿件生成失败，点击重试”），不需要理解“部分完成”这类复合状态术语
```


```gherkin

When 用户确认导入
Then 系统按确认时的最新权限拒绝操作
And 不把导入标记为成功
```

## 技术可行性核对

### 结论

本功能**有条件可行，首期不需要扩展 Composition AST**。现有稿件模型已经能表达标题、大题分组、说明文字、题目、题号、分值、分页、答题区和参考答案模块；主要缺口在导入侧：当前抽取结果只有题目列表，整卷结构在进入审核页之前已经丢失，无法仅靠现有 `questions[]` 还原原卷。

因此，本期的必要改造不是新增稿件节点类型，而是：

1. 扩展抽取结果，使其同时返回题目内容和有序整卷结构。
2. 在审核过程中保留结构节点与临时题目 ID 的关联。
3. 由服务端统一完成题目入库、稿件创建和 AST 写入，不由前端串联多个现有接口。

### 现有 AST 覆盖矩阵

| 原卷结构 | 现有表达方式 | 首期结论 |
| --- | --- | --- |
| 试卷名称 | `Composition.title` | 可直接复用 |
| 大题标题 / 分组 | `heading`（1-4 级） | 可直接复用 |
| 大题说明 / 题间文字 | `rich_text` | 可直接复用 |
| 题目 | `question`，引用入库后的题目 ID 并冻结快照 | 可直接复用 |
| 原题号 | `question.props.number` | 可直接复用 |
| 题目分值 | `question.props.score` + `scoring_enabled` | 可直接复用 |
| 分页 | `page_break` | 可直接复用 |
| 答题区域 | `answer_space` | 可直接复用 |
| 参考答案 / 解析汇总 | `question_details` + 派生的 `answer_item` | 可直接复用 |
| 多栏、浮动图文、复杂表格等版式 | 无等价结构 | 按 US-02 降级为可编辑富文本并提示 |

### 已确认的导入侧缺口

1. 后端 `AIQuestion` 和共享 `RawQuestion` 契约没有试卷标题、分组、原题号、分值、题间说明或布局节点。
2. `/upload/*` 只返回 `questions[]`；前端 `ExtractedQuestionItem` / `ImportDraft` 同样没有整卷结构字段。
3. 标签精准解析会忽略第一道题之前的前言，并主动跳过大题标题，只留下告警；这些信息无法在后续阶段恢复。
4. 当前前端把所有抽取题目的 `parent_id` 初始化为 `null`；材料题父子关系没有稳定传到审核与入库载荷。
5. `POST /questions/batch` 返回创建后的题目列表，但请求没有客户端临时 ID，响应也没有“审核项临时 ID → 数据库题目 ID”的显式映射；依赖数组位置建立稿件引用不够稳健。
6. 当前批量入库会先提交 `ImportTask`，题目创建与后续独立的组稿 API 不在同一个事务边界内；直接由前端依次调用会放大部分成功和重试重复的风险。
7. `ImportTask` 目前没有文件内容哈希、关联稿件 ID、来源快照或稿件创建子状态字段。

### 建议的最小技术边界

抽取结果新增一个“整卷包络”，不要直接复用 Composition AST 作为 AI/解析器输出。解析器只描述识别事实，稿件服务负责把它翻译成合法 AST：

```text
PaperExtraction
├── suggested_title
├── questions[]          # 每题带稳定 temp_id，可含 parent_temp_id
└── outline[]            # 有序结构：heading / rich_text / question_ref /
                         # page_break / answer_space / details_module
```

其中 `outline.question_ref.temp_id` 指向 `questions[].temp_id`。审核页删除、复制或调整题目时同步维护该引用；确认入库后，由服务端使用显式的 `temp_id → question_id` 映射生成 question 节点。

确认流程建议新增一个服务端编排入口，至少完成以下职责：

1. 对选中题目、空间、目录和整卷结构做一次预检，先返回不可导入项和降级提示。
2. 用户对部分失败作出“继续 / 取消”选择后，再提交最终确认请求。
3. 使用客户端生成的幂等键，避免网络重试重复创建题目或稿件。
4. 在服务端事务中创建导入任务、题目、稿件和节点；所有 DB 校验应在提交前完成。
5. 返回题目结果、稿件结果、跳过项、降级项及 `temp_id → question_id` 映射。

由于抽取完成后这些操作都在同一数据库内，正常路径应优先采用原子事务，尽量消除“题目已入库但稿件创建失败”。US-06 的独立稿件子状态和重试能力保留为异常恢复边界，而不是把部分成功设计成常态流程。

### 风险判断

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| AST 表达基础试卷结构 | 低 | 所需节点和属性均已存在，并已有模型与编辑器测试 |
| 抽取整卷层级与题间内容 | 高 | 当前契约会丢失，AI 与标签解析两条路径都需调整 |
| 材料题父子关系 | 高 | 当前审核草稿会清空 `parent_id`，需用临时 ID 显式建模 |
| 入库题目与稿件节点映射 | 中 | 需新增稳定 `temp_id` 映射，不能依赖数组位置 |
| 事务、幂等与异常恢复 | 中 | 现有服务可复用，但需要新增统一编排边界 |
| 文件级重复提示 | 中 | 需在上传时计算并持久化文件内容哈希；现有模型未保存该字段 |

### 技术验收门槛

进入完整开发前，应先完成一个纵向最小验证：用一份包含“试卷标题 → 两个大题标题 → 大题说明 → 三道题（含一道材料题及子题）→ 分值 → 参考答案”的固定样例，同时通过 AI 抽取与标签精准解析，证明两条路径都能产出同一语义的 `PaperExtraction`，并能转换为通过后端校验的 Composition AST。若该验证失败，应先修复抽取契约，不应继续堆叠确认页 UI。

## 范围

### In Scope

- 在现有智能导入确认流程中增加“同时保存为稿件”的结果选择。
- 从同一批审核通过的题目形成一份可编辑稿件草稿。
- 保留题目顺序、母子题关系，以及可识别的标题、分组、题号和分值；支持用户选择是否重排题号。
- 支持用户手动选择稿件的个人/共享空间及目标目录，并遵守现有权限与私有题限制。
- 支持用户编辑默认稿件名称。
- 检测并提示“文件内容与历史某次导入完全一致”的重复上传，不阻塞用户继续导入。
- 在完成结果和导入历史中展示题目、稿件及其关联状态。
- 支持部分题目入库失败时由用户决定继续或取消创建稿件，以及稿件创建失败后的独立、安全重试。
- 生成后的稿件继续使用现有编辑、复制、定稿和导出能力。

### Out of Scope

- 原 Word、图片或 PDF 的字体、页眉页脚、分页、边距、水印、装订线等像素级还原。
- 自动修复无法识别的复杂排版；首期仅提示用户检查并允许后续编辑。
- 导入后自动定稿、自动发布、自动导出或自动创建评测。
- 将多个文件自动合并为一份稿件，或把一份文件自动拆成多份稿件。
- 在同一次导入中创建多个差异化试卷版本。
- 改变现有题目审核、发布和可见性规则。
- 对题目内容层面的近似重复（同一试卷重新排版、部分题目增删、OCR 或抽取文字差异）做精准查重；首期只识别文件内容完全一致的重复上传。

### 依赖

- 现有智能导入能够产出经用户审核确认的题目列表。
- 现有稿件支持创建草稿、题目编排、保存、复制、定稿和导出。
- 学科成员权限、题目公开/私有规则及个人/共享稿件规则保持有效。

## 已确认的产品决策

1. “同时保存为稿件”默认关闭，由用户每次主动勾选开启（见 US-01）。
2. 稿件的个人/共享空间及目标目录均由用户在确认导入前手动选择，不做默认归属假设（见 US-03）。
3. 稿件默认名称取自可识别的试卷标题或导入文件名，导入确认前用户可修改（见 US-03）。
4. 审核后是否重排题号，由用户在确认导入时选择（见 US-02）。
5. 部分题目入库失败时，由用户决定是否仅用已成功题目继续创建稿件，还是取消本次创建（见 US-06）。
6. 当原卷结构超出稿件模型可表达范围时，一律降级保留内容、不丢题、不阻塞整份稿件生成，并在完成结果中提示教师手动补充（见 US-02）。
7. 重复导入只做“文件内容完全一致”的低成本、高精度提示，不阻塞用户继续；题目内容层面的近似重复识别不在首期承诺范围内（见 US-01）。
8. 首期整卷结构还原的达标标准是“教师无需手动调整即可认出这是同一份试卷”这一体验门槛，而非逐字段的颗粒度清单；标题、大题分组、题目顺序、题号、分值是达标底线，说明文字与参考答案模块可低于此线，走降级规则（见 US-02）。
9. 题目入库结果与稿件创建结果彻底解耦：导入任务本身不新增“部分完成”这类复合状态值，稿件创建作为独立可重试的子状态单独展示（见 US-06）。
10. 来源文件名、导入批次和时间在稿件创建时即固化为不可变快照，不因原始文件后续被删除或清理而失效（见 US-05）。

## 待评估的简化方向（可选，不影响本期范围）

以下并非本期决策变更，仅记录后续可考虑的简化方向，目标是减少确认流程中需要用户做选择的次数：

- US-02 的题号处理（重排 / 保留原题号）目前是一次性弹窗决策；可考虑改为默认“重排并连续编号”，并在稿件里保留可随时切换的开关，而非在确认路径上先问一次。
- US-06 的部分题目失败处理目前是一次性弹窗决策；可考虑改为默认“仅用已成功题目继续创建稿件”，并在完成结果里显著提示被跳过的题目，用户事后手动处理，而不必在确认流程中先做选择。
