## 编写约定 {#conventions}

完整版见 `.github/copilot-instructions.md` 的 i18n 小节，要点如下：

- **组件内**：`const { t } = useI18n()`（自动导入），模板里写 `t('ns.key')`。静态属性要改成绑定写法：`:placeholder="t(...)"`。
- **不缓存翻译结果**：页面启用了 keepalive，翻译结果不能存进模块级常量或普通 `const`。选项数组、zod schema 放进 `computed`，或者数组里只存 key。
- **组件外**：composable 中 `await` 之后的代码、`lib/` 里的函数，用 `@/lib/locale` 的 `translate()`。
- **富文本**：用 `<i18n-t scope="global" keypath="..." tag="span">` 加具名插槽，参考 `LanShareDialog.vue`。必须写 `scope="global"`，否则会有 intlify 警告。
- **数量**：不用 vue-i18n 的复数语法 `|`，写成对任意数量都通顺的句子，例如 `已选 {count} 个` 译为 `Selected: {count}`。
- **转义**：消息里不能出现裸 `@` 或 `|`，需要时写成 `{'@'}`。
- **日期和数字**：不要直接调用 `toLocaleString()`，用 `formatDateTime` 等函数。
- **变量遮蔽**：`.map(t => …)` 这类参数名会遮住 `t()`，要改名。
- **key 命名**：按功能分组的 camelCase 嵌套，例如 `questions.filters.status`。通用词放 `common.*`，新增前先查有没有现成的。

### 内容语言：不翻译 {#content-language}

只翻译**界面展示用**的文案。下面这些中文属于"内容语言"，保持原样：

| 类别 | 例子 | 位置 |
|---|---|---|
| 解析器语法和用户照抄的模板 | 【题目】【答案】标签、模板示例、匹配用的正则 | `StructuredTemplateGuideDialog.vue`、`import/smart.vue` |
| 和后端约定的格式 | Excel 列名（用户名、名称、一级目录……） | `manager/*ImportDialog.vue` |
| 写进稿件或导出的文本 | 默认模块标题"参考答案"、`（X 分）`、"每空 N 分"、【答案】排版标签 | `lib/compositionDocument.ts`、`compositionSnapshot.ts`、`ModuleBlockView.vue` |
| 发给 AI 的内容 | 工具定义和工具返回值、稿件大纲、中文题型名 | `lib/compositionPrimitives.ts`、`compositionOutline.ts`、`answerFormat.ts`、`use*AiTools.ts` |
| 纯文本答案值 | 判断题的"正确/错误"纯文本、分隔符 | `lib/answerFormat.ts`、`richDoc.ts` |
| 后端数据 | 设置项 description、后端返回的提示和日志 | `pages/settings.vue` 等 |

**例外**：用户之后可以修改的"默认名称"跟随界面语言，例如新建稿件的默认标题、新会话标题、预设服务商名称。

把"后端值 → 显示名"的映射改成 key 映射时，传给后端的值必须保持不变。

## 翻译工作流

在 `frontend/` 目录下执行：

```bash
# 1. 在 zh-CN.json 中新增或修改 key，代码里写 t('...')
pnpm i18n:sync    # 以 zh-CN 为准重排、清理其他语言，导出缺失和过期条目到 i18n/.pending/<locale>.json
# 2. 委派「翻译」agent：读 .pending/<locale>.json 和 glossary.json，只写 .pending/<locale>.out.json
pnpm i18n:apply   # 校验 key、{占位符}、语法、中文残留后合并；被拒的条目留在 pending 里
pnpm i18n:check   # 只读校验，含硬编码中文检查（app/lib/__tests__/i18n.test.ts 也会运行）
```

- **硬编码中文检查**：`check` 会扫描 `app/` 下 `.vue` / `.ts` 的非注释中文行（不含测试），不在 `i18n/.hardcoded-baseline.json` 里的都会报错。基线按「文件 → 整行文本」记录，与行号无关，所以改动已登记的中文行也会触发。确认是[内容语言](#content-language)后执行 `pnpm i18n:baseline` 重新登记，提交时检查基线的 diff。注释识别是启发式的：只认 `<!-- -->`、行首的 `/* */`、前面有空白的行内 `/* */`、前面不是 `:` 的 `//`。
- **过期检测**：中文原文改了，对应译文会被标记为 `stale` 并重新导出。重新翻译之前，旧译文仍然会显示。
- **并行批次**：每个 worker 把新 key 写进 `i18n/.fragments/<批次>.json`，不直接改 `zh-CN.json`。完成后执行 `pnpm i18n:merge` 合并：完全相同的条目自动去重；值不一样时整体中止，不写任何文件。
- **大批量翻译**：pending 超过约 500 条时，可以按顶层命名空间拆成多份，交给多个翻译 agent 并行处理，最后合并成一个 `en-US.out.json` 再 apply。这一步现在是手工操作，见[待办](#tooling)。
- **新增语言**：在 `nuxt.config.ts` 的 `locales` 和 `lib/locale.ts` 的 `SUPPORTED_LOCALES` / `DATE_FNS_LOCALES` 中注册，新建一个空的 `locales/<code>.json`，在 `glossary.json` 里加上该语言的术语，然后从 `sync` 开始走一遍流程。
- `.pending/` 和 `.fragments/` 已加入 gitignore。

### 第二阶段：后端

#### API 错误码

现状：

- `HTTPException` 有 137 处，`DomainError` 及其子类的 raise 约 76 处（其中组稿服务约 40 处）。带中文的单行 raise 约 120 处，另有一部分是英文（例如 `deps.py` 的认证错误），所以**中文界面下也会弹出英文错误**。
- `DomainError`（`capabilities/errors.py`）只有 `detail` 字段，`main.py` 的异常处理器返回 `{"detail": ...}`。
- 后端没有读取 `Accept-Language`。
- 前端的 `lib/apiErrors.ts` 和 `useAIConfigApi.apiErrorMessage` 直接显示 `detail`；422 校验错误取 `detail[0].msg`，内容是 pydantic 生成的英文。
- `import/smart.vue` 用 `detail.includes('未能入库')` 判断部分失败，是目前唯一按后端中文做字符串匹配的地方。

方案：

- **响应格式向后兼容**：`{"detail": "中文原文", "code": "upload.file_too_large", "params": {...}}`。`detail` 保留，作为还没迁移的 raise、旧客户端和日志的回退。
- **后端**：`DomainError` 增加可选的 `code` / `params`；为 HTTPException 提供一个带 code 的子类或辅助函数，在 `main.py` 中统一序列化。错误码集中登记在一个枚举里。
- **前端**：`getApiErrorDetail` 优先用 `apiErrors.<code>` 翻译，找不到 key 时回退到 `detail`。key 放在 `zh-CN.json` 的 `apiErrors.*` 下，走正常的翻译流程。
- **422 校验错误**：按 pydantic 的 `type`（`missing`、`string_too_short` 等）映射成通用文案，字段名暂时不翻译。
- **守门**：后端测试读取 `frontend/i18n/locales/zh-CN.json`，断言枚举里每个错误码都有对应 key。
- **已落地（第 3 步）**：`app/core/api_errors.py` 提供 `ErrorCode` 枚举和 `ApiError(HTTPException)`，`DomainError` 增加可选 `code` / `params`，`main.py` 统一序列化。前端 `getApiErrorCodeMessage` / `getApiErrorDetail` 按 `apiErrors.<code>` 翻译。新增错误码必须同步写入 `zh-CN.json`（`tests/test_api_error_codes.py` 校验）。已迁移：`deps.py`、`login`、`setup`、`upload` 中固定文案的 raise；`str(e)` 形式的动态错误暂保持原样。
- **已落地（第 4 步 · 导入）**：`import_tasks` 端点（`import_task.*`）和整卷导入 `paper_import_service`（`paper_import.*`，`PaperImportError` 带 `code` / `params`）已迁移。预览响应新增 `blocking_code` / `blocking_params`。`smart.vue` 改为判断 `code === 'paper_import.partial_skipped'`，不再匹配中文。`SkippedQuestion.message`（pydantic 校验原文）仍是原样，未本地化。剩余批次：`composition_service`、`ai_config_service`、`chat`、其余。`OAuth2PasswordBearer` 自带的 401 "Not authenticated" 不经过 `ApiError`，没有 code。
- **已落地（第 4 步 · 组稿）**：`composition_service`、`capabilities/compositions.py`、`capabilities/base.py` 的面向用户错误已迁移（`composition.*`、`auth.forbidden`）。AST / 结构校验类错误（节点引用缺失、answer_space 规则等）面向 AI 工具和开发者，刻意保留英文 `detail`。`plugins/api.ts` 在 `onResponseError` 中把带可翻译 `code` 的 `detail` 替换为当前语言文本，所有读取 `e.data?.detail` 的调用点自动本地化；因此前端不得再用 `detail` 的文字做逻辑判断（`useCompositions` 已改为按 `code` 分类）。
- **已落地（AI 提示词的输出语言）**：提示词正文只维护一份（中文），不按界面语言复制。`LocaleMiddleware`（`app/core/locale.py`）把 `Accept-Language` 解析成 `zh-CN` / `en-US` 放进 ContextVar，业务代码用 `get_locale()` 读取。`apply_output_language`（`prompt_utils.py`）追加一段输出语言指令：chat 与 solve 跟界面语言走，extract 固定为"保持原文语言、不翻译"（英文界面也可能导入中文试卷）。默认提取 / 解析提示词里有 `{output_language}` 占位符（位于文档块之前），学科覆盖里没写占位符时指令追加到末尾。导入任务在创建时把界面语言存入 `import_tasks.locale`，worker 执行前用 `set_locale` 恢复。前端 `plugins/api.ts` 已统一给每个请求带 `Accept-Language`；绕过它的原生 `fetch`（聊天流式）需自己带上，新增原生 `fetch` 时同理。学科设置页里展示的默认提示词仍是中文，属于内容，不随界面语言翻译。
- **分批顺序**：① ✅ `deps.py`、`login`、`setup`（每个用户都会碰到）→ ② ✅ `upload`、媒体 → ③ ✅ `import_tasks`，同步修改 `smart.vue` 的 `未能入库` 判断 → ④ ✅ `composition_service` → ⑤ `ai_config_service`、`chat` → ⑥ 其余。

### 第三阶段：体验

- **浏览器语言检测**：不要直接打开模块的 `detectBrowserLanguage`，它会和 `plugins/i18n.ts` 里的 `qb_locale` cookie 逻辑形成两套机制。改为在插件中处理：没有 cookie 时按 `navigator.languages` 选择语言，然后写回 cookie。
- **布局适配**：英文文案普遍比中文长，按钮、侧边栏、表格列宽还需要逐页目测检查。目前只验证了文案，没有做系统的视觉检查。可以按上面「迁移批次记录」的顺序逐页截图对比。

### 第四阶段：内容多语言（按需）

- 导出（DOCX / LaTeX）的【解析】、大题序号等，应跟随试卷或学科的语言设置，而不是界面语言。
- AI Prompt（`backend/app/services/prompts.py`、`importing/prompt.py`）准备多语言版本，或者指定输出语言。
- 导入解析器（`structured_parser`、`importing/normalize`）支持英文标签和格式。
- 前端里对应的内容语言常量（上表）要和上面这些一起改。

### 工具改进 {#tooling}

- `i18n:sync` 可以增加 `--split <n>` 参数，自动按命名空间拆分 pending；`apply` 也能接收多个 out 文件。
- 项目里没有装 `vue-tsc`，`pnpm exec nuxi typecheck` 也会因为 tsconfig 的 `TS5094`（`--noEmit` 与 `--build` 冲突）失败，所以 `.vue` 文件没有类型检查，目前只靠 `pnpm generate` 构建来把关。

## 本地验证

在临时数据目录里启动后端，不会影响 `backend/app.db`：

```bash
cd backend
D=$(mktemp -d /tmp/qb-i18n-XXXX)
export DATA_DIR=$D DB_URL=sqlite+aiosqlite:///$D/app.db CHROMADB_MODE=embedded
uv run python -c "from app.core.config import get_db_url; from app.db.migrations import run_migrations; run_migrations(get_db_url())"
uv run python scripts/create_superuser.py          # admin / password
PORT=8765 OPEN_UI=0 uv run python run.py --server

# 另开一个终端
cd frontend && API_BASE_URL=http://127.0.0.1:8765 pnpm dev
```

切换语言：登录页右上角的按钮，或者侧边栏用户菜单 → 语言。也可以直接设置 cookie `qb_locale=en-US`。首次打开某个页面时，Vite 可能会重新优化依赖，出现 504 或页面卡在"加载中"，刷新一次即可。
